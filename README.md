# ovk-bot-starter
Простая самописная микролибка для создания ботов в ОпенВК, лежит в core.

main.py - файл-демо с примером кода.

## Requirements:
- Pydantic
- httpx
- dotenv

## Current Version
0.4.1.hotfix

### Description
HOTFIX! Запрос обновлений поллинга работает асинхронно, фильтры используют async def в call'е. По мелочи: убрал лишние дебажные сообщения в терминале.

## WARNING!
В версии 0.3.1 произошли изменения для клиентского кода. 

### Было:
```
api = OvkApi(creds or token)
```

### Стало:

```
api = OvkApi.by_token(token)
```
или
```
api = OvkApi.by_credentials(login, password)
```

## WARNING!!!!
В версии 0.4 произошли изменения клиентского кода

### Было(DEPRECATED AND WILL BE REMOVED):
```
await api.long_poll_async() 
```

### Стало 
```
await api.start_polling
```

## WARNING!!!!
В текущей версии произошли ломающие изменения.
Message более не имеет полей args и args_rest.
Парсинг аргументов происходит перед непосредственно вызовом функции.
Единственное изменение - tail парсинга теперь даолженн быть аргументом функции обработчика. 
Пример - в main.py.

## Установка и запуск

### Подготовка файлов
1. Клонируйте репозиторий через git clone или скачайте исходный код
2. .env.example переименуйте в .env и укажите в нем креденшлы или токен

### Подготовка окружения

#### Создание виртуального окружения 
``` 
python -m venv .venv
```

#### Актвиация и подготовка окружения
##### Linux
```
source .venv/bin/activate
```
##### Windows
```
.venv/Scripts/activate
```
(я не помню как под виндой, просто загугли сам)

##### Установка зависимостей
```
pip install -r reqs.txt
```
#### Запуск
```
python main.py
```

### 0.2.2 Description
- api.send_message (и прочие обращения) из хендлера теперь необязателен
- api в di теперь необязателен
- отправка ответа и реплая теперь может производиться из сущности message
- для отправки фото теперь достаточно создать объект класса Photo из core.types и в path= указать путь к пикче, затем передать объект в msg.answer или msg.reply как аргумент photo=
- Ошибки в хендлерах теперь не кладут всего бота, в выводятся в принт.
- 0.3 Аргументы для команд, парсинг и проброс в обработчик по именам.
- 0.3.1 Изменение способа получения объекта класса OvkApi, небольшой рефактор 
- 0.4 REFACTOR! Управление лонгполлом выведено из-под ответственности OvkApi в класс LongPollServer. OvkApi теперь работает с получаемым от ЛПСервера списком объектов ивентов.
- 0.4.1 REFACTOR! Очень серьезно перебран цикл поллинга, чуть сильнее разделена ответственность. Message создается только под самый хендлер, на протяжении остального жизненного цикла - LongPollEvent. В будущем позволит обрабатывать и другие типы событий. Также, сборка кваргов и парсинг аргументов команды происходят лишь перед самым вызовом обработчика.
